## D-001 (2026-09-10) — Rule count is nine core + one stretch
The proposal deck says "ten deterministic rules"; the catalog defines nine (G-01..G-07, G-09, G-10) after G-08 silent-REWRITE was removed (semantics change without consent). Going forward: "nine core rules (ten with stretch G-10)". Deck wording corrected at the next deck touch.

## D-002 (2026-09-10) — G-05 checks projections, not predicates
A WHERE clause that filters on a sensitive column (corpus B-11: `COUNT(*) ... WHERE paid = 0`) is not exfiltration; only the SELECT list can leak values. G-05 inspects projections only; star projections expand against table metadata. Without this, three benign corpus entries would be false positives.

## D-003 (2026-09-10) — G-09 is PASS + suggestion, not a block
TECH_PLAN §2 sketched G-09 as "block + corrected query", but corpus B-02/B-10/B-12 are deliberately unbounded benign selects expecting PASS. Decision: missing LIMIT on a non-aggregated SELECT yields verdict PASS with a SUGGEST action and a human-readable note. Blocking would break the FPR < 10% target by design.

## D-004 (2026-09-10) — Unparseable candidates BLOCK (rule id PARSE)
A candidate that fails normalized parsing never reaches the executor. Safe-by-default; the audit log records the raw SQL and the parser error so corpus growth can add the case.

## D-005 (2026-09-10) — G-10 (semantic mismatch) is stretch
True intent-vs-shape comparison needs an intent representation; the mock corpus case (A-SEM-01) is verdict-covered by G-01/G-02 because its candidate is a DELETE. Kept in the SRS as FR-G10 [stretch], droppable per the capacity plan without losing the demo.

## D-006 (2026-09-10) — Verdict-level corpus matching
The CI gate (`--fail-on-miss`) compares expected VERDICT (PASS/BLOCK), not rule attribution. Rule attribution stays in the report for analysis. Rationale: several candidates legitimately fire a different (earlier-precedence) rule than the corpus label while producing the same safe outcome (e.g., A-WBP-02 candidates fire G-01, label says G-03).

## D-007 (2026-09-10) — prescriptions.date added to the demo schema
The B-07 corpus candidate (`WHERE date >= date('now','-7 days')`) references a column the §3 schema lacked; the integration test caught it as a runtime error. Decision: add `prescriptions.date TEXT` + seed values. This is a design-layer fix, not a code workaround.

## D-008 (2026-09-10) — MASK satisfies expected BLOCK in the harness
Read-exfiltration entries expect BLOCK; the gate's designed outcome is MASK (safe transformation, the project differentiator). Verdict comparison is safety-oriented: expected BLOCK is satisfied by BLOCK or MASK; expected PASS is satisfied by PASS only. MASKs are reported separately in class metrics so the number stays honest.

## D-011 (2026-09-12) — Compound SELECTs are verified arm by arm
The UNION bypass: gate.py ran the G-05 masking branch only for exp.Select roots, so UNION / UNION ALL roots skipped masking entirely (proven live pre-fix: `SELECT name FROM doctors UNION SELECT ssn FROM patients` returned PASS with SSN rows in the result). Policy: every SetOperation arm is verified recursively (sqlglot nests left-deep: Union(Union(A,B),C)); a non-SELECT arm BLOCKs; an arm projecting only sensitive columns BLOCKs; if any arm was masked the verdict is MASK (D-008 semantics); UNION vs UNION ALL is preserved (arms mutated in place, operator node untouched). G-09 does not apply to compound statements (results are bounded by the 50-row fetch cap in app.py). Alternative considered: BLOCK every compound SELECT — rejected: kills legitimate analytics without adding safety over per-arm verification. Residual (for the fuzz/metamorphic unit): set operations nested inside subqueries fall under outer projection masking, not arm verification. Corpus: A-EXF-06, A-EXF-07; tests: 4 new in test_rules.py.

## D-012 (2026-09-12) — Sensitive columns are blocked in GROUP BY / ORDER BY / HAVING
Projection-only checks (D-002) leak through side channels: GROUP BY ssn returns one row per distinct SSN (cardinality leak), ORDER BY ssn is an ordering oracle; the schema-inference literature (NAACL 2025, LITERATURE_REVIEW §3.3) shows full reconstruction from a handful of probes. Policy: references to sensitive columns in group/order/having BLOCK (G-05); WHERE stays allowed (corpus B-11 depends on it; D-002 stands). Corpus: A-EXF-08, A-EXF-09. FPR guard: no benign corpus candidate groups or orders on a sensitive column (checked all 30 before the change).
